cmux-picker demo

A page for exercising the element picker by hand. Load the unpacked extension (npm run build, then dist/extension/ at chrome://extensions), then use it here: hover highlights the element under the cursor, click picks it and opens the popup, shift+click adds more.

Ctrl+B arms the picker (the toolbar icon does the same thing)

Each card's "Expected" line describes the Focus line and path in the prompt the agent receives, not the popup: the popup and hover chip show a shortened version with the parenthetical stripped for width, hover either one for the full text in a native tooltip. With no cmux reachable, typing a prompt and pressing Enter copies the same text to your clipboard, which is the easiest way to check these by hand.

1. No locator attribute

Plain markup, nothing points back to a source file.

Expected: Focus: none, find by selector

2. data-loc on the clicked element

The locator attribute sits directly on the element you click.

Expected: Focus line ends with " (data-loc)"

3. data-loc on an ancestor

The locator is on a wrapper; you click a plain child inside it.

Click this label

Expected: Focus line ends with " (data-loc, ancestor)"

4. data-insp-path

A React-inspector-style locator attribute.

Expected: Focus line ends with " (data-insp-path)"

5. data-asl

Another framework's source-locator attribute.

Expected: Focus line ends with " (data-asl)"

6. Precedence: two locators on one element

This element carries both data-v-inspector and data-loc. SOURCE_ATTRS checks data-v-inspector first, so it wins.

Expected: Focus line ends with " (data-v-inspector)", never " (data-loc)"

7. Selector path with an id

A qualifying id stops the path at one segment; a non-qualifying one falls back.

Qualifying id
id="build-info"
Id that ID_RE rejects (starts with a digit)
  • alpha
  • id="123-not-valid"
  • gamma

Expected: the first picks div#build-info, a single segment (selectorPath stops at tag#id). "123-not-valid" starts with a digit so ID_RE rejects it; the picker falls back to sibling position, so the path ends in li:nth-of-type(2).

8. Selector path with classes

Three classes on this element; only the first two survive.

class="card-title lead extra"

Expected: path ends in div.card-title.lead (extra is dropped; at most two classes are kept, in source order)

9. Selector path with neither id nor class

Plain siblings with no id or class fall back to position among same-tag siblings.

  • first
  • second
  • third, click me
  • fourth

Expected: clicking "third" ends the path in li:nth-of-type(3)

10. Depth cap

Nine plain, unclassed, unidentified div wrappers around the target below (open DevTools to confirm the real nesting).

Click me

Expected: selectorPath climbs at most 6 segments (segments.slice(0, 6) in dom.ts), so the path shows only the nearest 6 levels and drops the rest

11. Open shadow DOM

A custom element with attachShadow({ mode: 'open' }) holding a button.

Expected: picking the button crosses the boundary; the path contains " >>> "

12. Closed shadow DOM

Same, but attachShadow({ mode: 'closed' }). The picker cannot see inside a closed root.

Expected: the picker cannot reach the inner button; the host element itself is picked

13. iframe

Points at a srcdoc document, so it needs no network. The picker is injected only into the top frame (no allFrames), so click the dashed padded edge, not the button inside.

Expected: clicking the padded edge (still the top document) picks the iframe element itself; the markup renders as <iframe ...>...</iframe> (a COLLAPSE_TAG). Clicking the inner button does nothing: it is inside the frame's own document, which this picker never sees.

14. Inline SVG shape

Clicking the shape should never pick the shape itself.

Expected: clicking the circle or the path picks the closest ancestor svg, never the shape (and the svg's own markup renders collapsed too, svg is also a COLLAPSE_TAG)

15. Truncation

An attribute value and a text node that both exceed the picker's caps.

This paragraph keeps going well past the picker's text cap so you can watch the copied prompt cut it off partway through this very sentence.

Expected: the 90-character data-config value truncates to its first 77 characters plus "..." (80 total, truncateAttr); the 140-character text truncates to its first 117 characters plus "..." (120 total, truncateText). Pick it, type any prompt, press Enter with no cmux reachable (an empty prompt just flashes red) to copy it, and paste it somewhere to see the exact cut.

16. Multi-select

Shift+click chips to build a selection (each gets a numbered outline); a plain click finishes and opens the popup. Try shift+clicking all six: the sixth shows a toast instead of adding.

Expected: up to 5 total (MAX_SELECTION in picker.ts). A 6th shift+click shows a toast "Up to 5 elements" instead of adding it; a plain click (no shift) always finishes and opens the popup, whether or not you shift+clicked anything first. In the outgoing markup the first chip you shift+clicked is the primary (data-cmux-picked=""); the rest are numbered 2 and up, in the order added, with the finishing plain click's chip appended last if it wasn't already selected.

17. Big subtree, over the inline limit

Pick a row from the middle of the list (not the first two or last two: those show fewer neighbors and stay under the limit).

    Expected: only observable end to end with a live cmux target (the clipboard fallback always inlines the full markup). The rendered attachment for a middle row is well over native.ts's 1500-character inlineMaxChars, so a real send writes it to a file and the prompt shows a "Details: <path>" line instead of inlining the snippet.

    18. Attach screenshot

    A visually distinctive block to try the "Attach screenshot" toggle in the popup (it appears once cmux reports screenshot capture is available).

    Bright gradient block, easy to spot in a screenshot

    Expected: the screenshot is the real pixels of this element plus a 40px margin (MARGIN in content.ts), cropped from the visible tab, not a re-render
